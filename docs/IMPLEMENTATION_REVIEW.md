# 구현·모델 품질 통합 리뷰 — 2026-09-25

**구현의 실행 안정성은 개선됐지만, 실제 사진에서 방향과 페이지 영역을 알아내는 능력이 부족하다. 다음 개발은 방향·위치·크기 추정을 분리하는 데 집중해야 한다.** 새 해석적 좌표 모델은 접힘을 줄였지만, 페이지 안쪽의 작은 영역만 확대하는 결과가 남는다. 평균 좌표 오차나 렌더링 성공만으로는 이 문제를 발견하기 어렵다.

이 문서는 9월 25일의 재현 검사·보관 기록·향후 제안을 통합한다. 당시 변경 범위는 리뷰와 README였다.

9월 26일 반영: 방향·마스크·모서리 감독, 품질 기반 후보 선택과 XPU 학습·재개를 구현했다. `teacher` 방향 학습은 심한 누락을 줄였지만 교체 기준을 통과하지 못했다. 기록은 [direction.json](../outputs/coordinate-fold/direction.json)에 있다.

## 3. 최근 후보의 개선과 퇴행

다음은 같은 validation 528장에 대한 보관된 정식 비교다. 그중 촬영 48장의 선택 모델·Surface 초기값·배경 증강 후보는 이번 로컬 재실행과 평균 EPE 차이 **0**이었다. 높은 해상도·회전 후보와 나머지 도메인은 보관 기록이다.

| 모델/설정 | 혼합 EPE | 자체 합성 384장 | 촬영 48장 | 사진 기반 휨 합성 96장 | 촬영 렌더링 실패 | 촬영 심한 누락 또는 진단 불가 | 촬영 coverage |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 현재 선택 global | 14.35 | 9.58 | 39.26 | 20.99 | 3 | 11 | 66.45% |
| Surface, 입력 192×144 | 11.38 | 9.25 | 21.71 | 14.73 | 0 | 12 | 73.05% |
| Surface, 입력 384×288 | 10.35 | 8.47 | 20.47 | 12.84 | 0 | 14 | 71.97% |
| 위 설정 + 배경 변경 50% | **10.26** | **8.40** | **20.27** | **12.65** | **0** | **13** | **68.70%** |
| 위 설정 + 이미지별 회전 15% | 11.07 | 9.04 | 20.67 | 14.35 | 0 | 13 | 69.10% |

단위와 정의:

- EPE는 정답이 유효한 출력 좌표에서 계산한 원본 작업 이미지 **384×288의 픽셀 거리**다. 카메라 원본 1080×1920 해상도의 픽셀이 아니다. 출력 좌표 평가 크기는 192×144이며, 모든 크기 표기는 `(H, W)`다.
- 각 이미지에서 평균을 구한 다음 이미지별 평균을 낸다. 렌더링 실패라도 유한 좌표 오차는 포함한다.
- `precision`은 요청한 모든 출력 중심 중 정답 페이지 안에 떨어지는 비율이다.
- `coverage`는 예측 좌표의 외곽선이 둘러싼 영역이 정답 페이지 영역을 얼마나 덮는지다. 글자 정확도나 글줄 직선성을 뜻하지 않는다.
- 심한 누락 진단은 precision 또는 coverage가 50% 미만인 경우다. 표의 합산 열은 계산 불가도 포함한다. coverage 평균은 계산 불가를 0으로 두어 전체 사례 수를 유지한다. 선택 모델의 촬영 48장 중 3장은 coverage 계산 불가였다.
- Surface 4개 설정은 초기 가중치에서 각각 12epoch 실행한 결과 중 혼합 EPE 최저 시점이다. 시점은 0·11·10·11epoch다. 첫 행과 달리 이 후보들은 기본 추론에 채택되지 않았다.

해상도·배경 변경은 Surface의 혼합 EPE를 약 9.9% 줄였다. 그러나 촬영 coverage는 **73.05% → 68.70%**, precision은 **90.00% → 92.50%**였다. 페이지 밖을 덜 읽게 됐지만 페이지 전체도 덜 읽는다. 이 조합과 아래 이미지 진단은 **페이지 내부의 작은 영역으로 수축하는 현상**을 보여준다.

자체 합성에서도 선택 모델의 coverage 96.25%에 비해 배경 증강 후보는 92.79%다. 촬영 EPE만 개선됐다는 이유로 선택 모델을 교체하면 내용 보존의 퇴행을 놓칠 수 있다.

## 4. 이번 추가 진단으로 확인한 원인

### 4.1 현재 좌표 디코더는 촬영 정답을 표현할 수 있다

촬영 48장의 정답은 네 모서리에서 만든 평면 homography다. 각 정답의 좌표 대응으로 homography를 최소제곱 적합하고, 이를 현재 Surface의 8개 projective 파라미터로 역변환했다. 40개 비선형 잔차 계수는 0으로 두었다. 이미지 인코더·학습·정답 기반 후보 선택은 사용하지 않았다.

| 항목 | 결과 |
| --- | ---: |
| 파라미터 허용 범위 안에서 표현 가능한 촬영 사례 | 48/48 |
| 디코더 출력의 평균 EPE | **0.00000444px** |
| 이미지별 최대 평균 EPE | **0.00000961px 미만** |
| 렌더링 실패·심한 누락 | 0 |
| 평균 coverage | 99.9991% |

따라서 **이 48장의 큰 오차를 해석적 좌표 표현력의 부족으로 설명할 수 없다.** 우선 의심할 곳은 이미지 특징, 방향·크기·위치 추정, 학습 자료와 목적 함수다. 9×7 격자를 무조건 키우는 처방에는 근거가 부족하다. Surface는 이 격자를 단순 확대하는 구조도 아니며, 최종 해상도에서 해석식을 직접 계산한다.

이 실험은 정답을 제공한 표현력 검사다. 자동 추론 성능이 좋아졌다는 결과가 아니고, 네 모서리 정답이 실제 종이 내부의 곡면까지 정확하다는 검증도 아니다. 자연 곡면과 심한 책등 변형에 대해서는 별도 적합 실험이 필요하다.

### 4.2 실패는 큰 회전 그룹에 집중된다

배경 증강 후보를 동일한 촬영 validation에서 다시 실행한 결과다. 방향 오차는 정답과 예측의 중앙 가로·세로 축을 원본 작업 이미지 픽셀로 바꿔 계산한 각도 차이다.

| 촬영 그룹 | 수 | EPE | 가로 방향 오차 | 정답 대비 가로 길이 | coverage | precision | 심한 누락 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `background01` | 12 | 10.02px | 5.27° | 1.011 | 89.79% | 87.54% | 0 |
| `background02` | 12 | 9.36px | 10.79° | 0.927 | 81.63% | 93.23% | 1 |
| `background03` | 12 | 11.24px | 4.00° | 0.877 | 81.02% | 89.28% | 0 |
| `background04` | 12 | **50.47px** | **65.21°** | **0.353** | **22.38%** | **99.94%** | **12** |

마지막 그룹은 페이지 방향이 대체로 ±90°다. precision만 보면 가장 좋은 그룹이지만, 실제로는 페이지 대부분을 놓친다. 예를 들어 첫 프레임의 coverage는 `datasheet004` 29.3%, `letter004` 19.2%, `paper004` 17.6%, `patent004` 26.0%다. 보관된 비교 이미지에서도 출력이 본문의 일부를 비스듬히 확대하는 것을 확인했다.

**배경 번호는 원인 변수가 아니다.** 촬영 방향·크기·원근도 함께 바뀌므로, 이 결과를 특정 배경색 때문에 실패했다고 단정할 수 없다. 방향을 고정하고 배경만 바꾸는 검사와 배경을 고정하고 방향만 바꾸는 검사를 나눠야 한다.

### 4.3 정답 방향을 알려줘도 크기 추정 문제가 남는다

정답 중앙 가로축의 각도를 가장 가까운 90° 배수로 나눠 원본 이미지를 회전했다. 같은 배경 증강 모델로 추론하고, 예측 좌표를 원래 이미지 좌표계로 되돌려 평가했다. 모델 가중치는 고정했다.

| 범위·항목 | 원래 추론 | 정답 방향을 알려준 추론 |
| --- | ---: | ---: |
| 촬영 전체 EPE | 20.27px | 14.16px |
| 촬영 전체 coverage | 68.70% | 75.13% |
| 촬영 전체 심한 누락 | 13/48 | 7/48 |
| 큰 회전 그룹 EPE | 50.47px | **23.79px** |
| 큰 회전 그룹 가로 방향 오차 | 65.21° | **5.04°** |
| 큰 회전 그룹 coverage | 22.38% | **50.32%** |
| 큰 회전 그룹 심한 누락 | 12/12 | 5/12 |

방향이 큰 병목이라는 증거다. 동시에 올바른 방향에 가까워져도 가로 길이 0.629배, 세로 길이 0.792배로 페이지를 작게 잡았다. 방향 분류기 하나만 추가해서 모든 오류가 해결되지는 않는다.

이 결과는 **GT를 사용하는 진단**이다. 배포 가능한 자동 방향 분류 결과나 보장된 성능 상한이 아니다. 90° 회전 시 이미지 종횡비와 전처리 조건도 달라진다. `background02`에서는 EPE가 9.36→11.59px로 나빠졌으므로, 추론에 일괄 회전 규칙을 넣는 것도 정당화하지 못한다. 방향 추정·페이지 검출을 각각 평가하고 전체 좌표 합성까지 확인해야 한다.

### 4.4 현재 보조 손실은 내용 보존을 보장하지 않는다

관련 구현은 [relative topology loss](/home/world/coding/flattener/src/flattener/learning/coordinate_study.py:962), [orientation loss](/home/world/coding/flattener/src/flattener/learning/coordinate_study.py:1191)다.

`relative topology`는 정답 Jacobian 대비 예측 면적 비율이 0.1보다 작을 때 벌점을 준다. 전체 페이지를 중심 기준 0.4배씩 줄이면 면적은 0.16배이므로 벌점이 없다. 32×32 항등 정답·384×288 원본 마스크로 직접 확인했다.

```text
predicted_map = 0.4 * identity_map
relative_topology_loss = 0.0
source_page_coverage = 0.16153067  # raster 경계 차이를 포함한 약 16%
```

이는 topology loss의 구현 오류가 아니라 역할의 한계다. 접히지 않는 변환과 페이지를 온전히 담는 변환은 다른 조건이다. 여기에 topology 가중치만 더 높여도 위 반례는 바뀌지 않는다. renderer의 양수 Jacobian 검사도 같은 이유로 이 문제를 잡을 수 없다.

현재 방향 보조 손실은 `1 - cos(angle)` 형태다. 예측과 정답이 정확히 반대이고 벡터 길이가 충분할 때, loss는 **2.0**이지만 예측 좌표에 대한 최대 절댓값 gradient는 **0.0**이었다. 동일한 180° 반례에서 기본 좌표 loss의 스케일 미분은 **+84.0**으로, 그 한 방향으로 gradient descent를 하면 스케일을 줄이게 된다. 이 작은 예는 방향이 틀린 상태에서 수축이 오차를 줄일 수 있음을 보여준다. 실제 전체 학습 경로를 증명하는 것은 아니다.

경계 가중치 3, 작은 페이지 추가 가중치 0.25, 방향 가중치 50, 회전 확률 0.5는 앞선 비교에서 이미 시도됐다. 이번 최근 비교도 회전 0.15를 포함했다. 따라서 **동일 구조에서 이 가중치나 확률만 반복 조절하는 것을 최우선 해결책으로 삼지 않는다.**

## 5. 구조·데이터·선택 방식에서 바꿀 부분

### 5.1 전역 회귀에 너무 많은 역할이 몰려 있다 — P1

[현재 인코더](/home/world/coding/flattener/src/flattener/learning/spatial.py:284)는 stride 2인 3×3 convolution 세 층, 채널 16·32·48, `AdaptiveAvgPool2d((6, 5))`, hidden 128을 거쳐 모든 파라미터를 예측한다. Surface는 전역 원근 파라미터 8개와 4×5×2 잔차 40개를 같은 전역 특징에서 출력한다.

입력을 384×288로 키워도 마지막 공간 특징은 6×5다. 입력 해상도 증가의 실제 개선은 확인됐지만, 작은 페이지의 세부 경계를 직접 감독하는 경로는 없다. `page` 구조에 별도 페이지 가지가 존재해도, 현재 Surface의 활성 경로에는 해당 출력이 없고 최신 설정의 `page_weight`는 0이다.

권장 구조는 다음 순서다.

1. **방향:** 0/90/180/270° 분류와 작은 잔여 각도. 의미가 있는 페이지 위쪽을 구분하고 각 방향별 confusion matrix를 남긴다. 빈 종이·방향 단서가 부족한 페이지는 불확실성을 허용한다. 같은 cosine 보조 손실만 추가하는 접근과 구분한다.
2. **페이지 영역:** 원본 좌표계의 페이지 mask와 의미 순서가 정해진 네 모서리 또는 경계점. 중간 해상도 특징을 유지한 작은 다중 해상도 head로 감독한다. 초기에는 페이지 검출만 따로 학습해 위치·크기 오류를 측정한다.
3. **정규화된 페이지 내부 보정:** 불확실성을 반영한 여백으로 페이지 영역을 잡고 원근을 정리한 뒤, 기존의 접힘을 억제하는 Surface 잔차부터 비교한다. 검출 오차와 곡면 모델 오차를 분리할 수 있게 한다.

단계마다 이미지를 반복 보간해 최종 출력으로 쓰지 않는다. 중간 입력은 특징 추출에 사용하고, 최종 backward map을 **원본 좌표계로 합성해 원본 RGB에서 한 번 샘플링**한다. 전처리 변환을 `T: original → normalized page`, 내부 예측을 `B: output → normalized page`로 정의했다면 최종 map은 `T⁻¹ ∘ B`다. 회전·padding·crop의 행렬과 half-pixel 규약을 메타데이터에 남겨야 한다.

학습 가능한 위치·스케일·회전 정규화를 분리하는 공개 기술 원리는 [Spatial Transformer Networks](https://arxiv.org/abs/1506.02025)에 설명돼 있다. 위 단계별 구성과 우선순위는 이번 저장소 진단에 따른 제안이며, 이 논문이 현재 프로젝트의 성능 향상을 보증하는 것은 아니다.

### 5.2 독립적인 영역·경계 감독이 필요하다 — P1

기존 좌표·경계·미분 손실은 유지하되, 페이지를 작게 잡는 문제를 직접 관측하도록 바꾼다.

- 원본 좌표계의 페이지 segmentation에 mask loss와 경계 감독을 추가한다. mask만 맞추고 방향이 뒤집히는 경우가 있으므로 의미 순서가 있는 모서리·방향 감독도 필요하다.
- 가로·세로 길이 비율, 중심 오차, 네 모서리 오차를 따로 기록한다. source 전체 크기보다 GT 페이지 크기로 정규화한 지표를 함께 사용한다.
- GT Jacobian 대비 면적·늘어남을 감독하는 항을 작은 별도 실험으로 비교한다. log 면적비 등을 쓸 때는 정답이 유효하고 가려지지 않은 셀만 사용하고, 작은 determinant 근처의 수치 안정성을 확인한다.
- coverage를 높이려고 배경까지 넓게 담는 반대 오류도 막아야 한다. precision·coverage·글자 누락을 함께 평가한다.
- 모델이 예측한 좁은 mask로 좌표 loss나 평가 분모를 줄이면 안 된다. 기존처럼 고정 GT 유효 영역을 기준으로 유지한다.

Surface의 접힘 억제 파라미터화는 유용한 기반이다. 이를 유지하면서 위치 추정을 개선하는 실험을 우선하고, 표현력 확인 없이 잔차의 제한만 풀어 접힘 문제를 되살리지 않는다.

### 5.3 학습 중 후보 보존과 최종 교체 기준을 연결해야 한다 — P1

[_validation_epe](/home/world/coding/flattener/src/flattener/learning/coordinate_study.py:1370)는 모든 검증 이미지의 단순 평균이고, [best 시점 갱신](/home/world/coding/flattener/src/flattener/learning/coordinate_study.py:1784)은 이 값만 비교한다. 반면 최종 후보 비교에는 실패·심한 누락·coverage·precision 조건이 있다.

현재 검증은 자체 합성 72.73%, 촬영 9.09%, 사진 기반 휨 합성 18.18%다. 촬영의 실패가 적은 비중으로 반영된다. 완료된 각 epoch는 원래 학습 폴더의 `.checkpoint-*`에 보존된다. 기존 정식 비교·최종 archive의 후보는 사전 선정한 best/last로 제한됐다. 중간 시점의 내용 보존은 별도 품질 평가가 필요하다.

권장 변경:

1. `best_epe`는 진단용으로 유지하고, **기존 품질 조건을 만족한 후보의 best**를 별도로 기록한다.
2. 각 도메인의 EPE·실패·coverage·precision·심한 누락을 학습 중 일정 간격으로 평가한다. 촬영처럼 작은 핵심 집합은 매 epoch 검사할 수 있다.
3. 프레임 평균과 문서 그룹 평균을 함께 기록한다. 도메인별 평균을 동일 가중치로 본 보조 점수도 남기되, 품질의 필수 조건을 평균으로 상쇄하지 않는다.
4. EPE·coverage·실패에서 서로 장점이 다른 후보를 제한된 수로 보존한다. 안전한 후보가 없으면 `best_eligible`이 없음을 그대로 표시한다.
5. 최종 교체는 기존 전체 validation 기준으로 결정하고, 후보와 기준을 고정한 뒤 독립 시험을 한 번 수행한다.

현재 교체 거부는 필요한 보호 장치다. 퇴행 조건을 느슨하게 바꿔 새 모델을 채택하는 것이 개선은 아니다.

### 5.4 데이터에서 방향과 배경이 얽혀 있다 — P1/P2

이번 manifest·메타데이터 재검사 결과:

| 학습 자료 | 좌표 학습 이미지 수 | 확인한 제한 |
| --- | ---: | --- |
| 자체 합성 | 3,840 | 회전 파라미터 약 −22.87°~22.91° |
| 사진 기반 휨 합성 | 1,584 | 회전 파라미터 약 −15.00°~14.79° |
| 실제 촬영 | 528 | 원본 264프레임의 광학 증강 포함, 이 중 큰 회전 그룹 132개 |
| 합계 | 5,952 | 큰 회전 촬영 그룹은 약 2.22% |

촬영의 22개 학습 템플릿은 관련 원문을 묶으면 14개 source group이다. validation 촬영 48장은 독립 문서 4종이며, 배경·프레임을 반복한 수다. 파일 수가 늘어도 같은 원문·같은 촬영의 변형이면 독립성이 그만큼 늘지 않는다. 새 후보들은 같은 validation을 여러 번 사용했으므로 여기서의 향상을 새로운 문서에 대한 일반화로 해석할 수 없다.

권장 조치:

- 원문·촬영 세션 기준 분할을 먼저 고정하고, 학습용 파생 이미지는 그 분할 안에서만 만든다.
- 배치 또는 sampling weight에 도메인·방향·페이지 크기를 반영한다. 중복 프레임을 과도하게 반복하지 않도록 원문 그룹을 먼저 뽑는 방식도 비교한다.
- 방향 분류 단계에서는 4방향을 균형 있게 노출하고 작은 연속 각도를 더한다. 전체 보정기의 합성 데이터도 방향·위치·크기를 서로 독립적으로 변화시킨다.
- 같은 페이지와 자세에서 배경만 바꾸는 자료, 같은 배경·페이지 크기에서 방향만 바꾸는 자료를 만들어 원인을 분리한다.
- 단일 seed의 작은 개선으로 설정을 확정하지 않는다. 효과가 있는 소규모 실험만 여러 seed로 확인하고, 비교 시 이미지 노출 수·optimizer step·학습 예산도 맞춘다.

SyntheticDoc 1,400개는 원문 그룹의 split 중복과 좌표 계약 검증이 남아 있어 학습에서 제외한다. [공식 원본 BM 생성식](https://github.com/tanguymagne/SyntheticDoc/blob/aabd9cf05f479781df432e3bd7e940f3e6716dbd/generation/backward_mapping/uv_to_backward_map.py#L53-L91)의 물리 좌표 변환은 `q = b + (1/W, 1/H)`이다. 원본 UV 1개의 내부 49점 재투영이 이를 지지했다(1차 source-pixel 역보정량 중앙값 0.000049px). 전량·가림 영역 검증은 남아 있다. 격자 중심을 페이지 모서리로 쓰지 않으며, 메타데이터 `orientation=180`은 [종이 앞·뒤 반전](https://github.com/tanguymagne/SyntheticDoc/blob/aabd9cf05f479781df432e3bd7e940f3e6716dbd/generation/rendering/mesh_loader.py#L106-L121)을 뜻하므로 사진의 방향 정답으로 쓰지 않는다.

### 5.5 증강은 좌표 정합 외에 시각적 부작용도 봐야 한다 — P2

[_protected_preview](/home/world/coding/flattener/src/flattener/learning/augmentation.py:124)는 페이지 mask를 원본에서 7×7, preview에서 다시 5×5로 팽창시켜 보호한다. 문자를 훼손하지 않으려는 합리적인 장치지만, 보관된 이미지에는 종이 주변의 기존 배경색 테두리가 남아 있다. 페이지가 작을수록 이 테두리가 검출 단서가 될 가능성이 있다. 실제로 그 단서에 의존한다고 입증된 것은 아니다.

[_fit_matrices](/home/world/coding/flattener/src/flattener/learning/augmentation.py:139)는 90/270° 회전 사진을 같은 캔버스에 맞춘다. 384×288에서는 물리적 선형 크기가 0.75배가 되고 여백이 생긴다. 따라서 회전 추가 실험은 방향·크기·padding 질감이 함께 바뀐다. 보관된 preview에서도 padding과 내부 배경 사이 경계가 보였다.

다음 비교에서는 종이 보호 조건을 유지하면서 테두리 폭을 변화시키고, 회전 여부에 따른 페이지 크기 분포를 맞춘다. 동일 장면의 GT RGB 재구성과 경계 오차도 검사한다. 단순히 보호 mask를 줄여 문자를 덮는 방식은 피한다. 증강 좌표 계약의 CPU 테스트는 이번에 통과했지만 CUDA parity는 이 환경에서 다시 실행하지 못했다.

### 5.6 자연 곡면·내용 보존의 정답이 부족하다 — P2

촬영 자료의 네 모서리 정답은 평면 근사다. 종이 내부의 실제 휨, 책등, 가림을 조밀하게 측정한 정답이 아니다. 사진에서 네 모서리로 만든 템플릿에는 조명·흐림·잔여 왜곡이 남을 수 있다. 그런 템플릿에 합성 변형을 추가하고 정확히 역변환해도 원래 템플릿의 왜곡까지 제거하도록 학습한 것은 아니다.

페이지 위치 추정 개선과 병행해, 다음 감독·평가 자료를 준비해야 한다.

- 직접 만든 평면 문서·벡터 글줄에서 생성한 곡면 정답: 변형 전 글줄과 문자 영역을 정확히 안다.
- 사용 조건이 확인된 실제 곡면 사진과 대응 평면 스캔: 페이지 누락, 글줄, 국소 대응점 또는 수작업 기준점을 추가한다.
- 책등·국소 휨·작은 문서·다단 편집·표·낮은 대비·그림자·가림을 나눈 실패 분류표.
- 같은 책·문서·촬영 세션이 학습과 시험에 섞이지 않는 새로운 시험 집합.

평면 위치가 해결된 다음 Surface의 40개 잔차를 GT에 직접 적합해 잔여 오차를 측정한다. 이 오차도 크면 디코더의 국소 표현력을 늘리고, 이 오차는 작지만 사진 추론만 나쁘면 특징·감독·자료를 먼저 개선한다. 경계와 글줄을 이용한 제약은 [Revisiting Document Image Dewarping by Grid Regularization](https://arxiv.org/abs/2203.16850)의 공개 연구 원리도 참고할 수 있다. 여기서는 원리를 검토했으며 외부 구현·가중치를 프로젝트에 가져오지 않았다.

출력 종횡비도 별도 평가해야 한다. 현재 API는 출력 크기를 호출자가 지정한다. 지난 별도 실사진 130장 진단은 참조 스캔의 종횡비를 사용한 유리한 조건이었다. 새로운 사용성 평가에서는 정답 종횡비를 제공한 조건과 실제 추론·사용자 지정 조건을 분리하고, 글자와 표가 가로세로로 늘어나는 현상을 기록한다.

### 5.7 `success`를 품질 합격으로 쓰면 안 된다 — P1

[추론 메타데이터](/home/world/coding/flattener/src/flattener/learning/inference.py:72)는 현재 `quality_status="not_evaluated"`를 명시한다. 이 구분은 올바르다. 그러나 사용자에게 나쁜 보정 결과를 자동으로 걸러주는 기능은 아직 없다. 큰 회전 그룹은 12장 모두 렌더링에 성공하면서 평균 22% 정도의 페이지 영역만 포함했다.

평가 때 사용하는 GT coverage를 서비스 추론에 그대로 사용할 수는 없다. 실제 추론에서는 별도로 추정한 페이지 영역, 방향 확신도, 변환이 포함한 영역, 모서리 일치, 글줄·글자 누락 신호를 이용한 품질 판정을 검토한다. 이 추정기도 실패할 수 있으므로 별도 검증 자료에서 **잘못된 보정을 통과시키는 비율**과 **정상 보정을 거부하는 비율**을 함께 측정한다. 출력 맵 자신의 유효성만 검사하는 장치는 대체재가 아니다.

불확실한 결과를 처리할 때 원본 복귀나 재촬영 안내가 발생했음을 보존하고, 실패 상태를 성공으로 바꾸지 않는다. 문서가 없는 사진·가려진 페이지·여러 페이지 입력도 품질 판정의 평가 대상이다. 현재 좌표 학습 데이터 어댑터는 페이지가 있는 양성 자료만 학습한다.

정식 평가기로 전체 validation을 다시 확인하려면 다음처럼 새 출력 경로를 사용한다. 선택 모델의 렌더링 실패 때문에 보고서가 완성돼도 종료 코드가 1일 수 있다.

```bash
review_output=$(mktemp -d /tmp/flattener-validation-XXXXXX)
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 .venv/bin/python -m flattener.learning.evaluation \
  --dataset outputs/dataset \
  --checkpoint outputs/coordinate-fold/selected.pt \
  --split validation --output "$review_output/report" \
  --output-size 192 144 --include-paper-augmentation
```

이번 추가 진단의 스크립트는 [recheck.py](/tmp/flattener-deep-review-Mpt8R6/recheck.py), 사례별 결과는 [local-recheck.json](/tmp/flattener-deep-review-Mpt8R6/local-recheck.json), 테스트 로그는 [pytest 로그](/tmp/flattener-latest-pytest.log)에 있다. 모델 가중치·사진을 저장소에 추가하지 않기 위해 기존 ZIP에서 필요한 후보와 preview만 임시 추출했다. 임시 파일은 시스템 정리 시 사라질 수 있으므로 주요 수치와 방법은 이 문서에 남겼다.

좌표 표현력 진단을 재작성할 때의 절차:

1. `SceneCoordinateDataset(..., split="validation", output_size=(192,144), include_paper_augmentation=True)`에서 `source_kind="capture"`인 48장을 사용한다.
2. 출력의 정규화 pixel-center 좌표와 GT source 좌표를 12픽셀 간격으로 취해 float64 최소제곱으로 `H`, `H[2,2]=1`을 구한다.
3. `t=H[:2,2]`, `p=H[2,:2]`, `A=H[:2,:2]-outer(t,p)`로 분리한다. `sx=||A[:,0]||`, `theta=atan2(A[1,0], A[0,0])`, `sy=det(A)/sx`, `shear=dot(A[:,0]/sx,A[:,1])`을 구한다.
4. `atanh([t, theta/π, log(sx)/3, log(sy)/3, shear/2, p/(0.6-sum(abs(p)))])`로 첫 8개 raw parameter를 만든다. 모든 입력이 허용 범위 안인지 검사하고 나머지 40개는 0으로 둔다. clipping은 하지 않는다.
5. 기존 Surface `_decode`를 float32로 실행하고 같은 GT 마스크·원본 픽셀 단위로 평가한다. 가중치나 이미지 인코더는 수정하지 않는다.

방향 진단은 GT 중앙 가로축을 물리적 source 픽셀로 바꾼 각도에서 `k=round(angle/90) mod 4`를 구하고, 원본에 `np.rot90(image,k)`를 적용한다. 예측의 정규화 좌표를 원본으로 되돌리는 식은 k=1에서 `(-y,x)`, k=2에서 `(-x,-y)`, k=3에서 `(y,-x)`다. 출력의 정답·평가 mask는 유지한다. 이 절차는 GT를 사용하므로 정식 추론 경로에 넣지 않는다.
